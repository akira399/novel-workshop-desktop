# 大肥鱼的小说工坊 优化方案

## 现状诊断

后端能力其实很全（86 条 IPC 命令、core 层 282 个测试、70 个提示词模板），但 UI 承载太弱——全部界面只有 1185 行单文件 App.tsx + 543 行全局 CSS，主要痛点：

1. **布局简陋**：无章节树（选章靠 `<select>` 下拉），无右栏；24 个工具按钮全部堆在左侧栏
2. **交互原始**：题材 id、文风 id、导出格式、阶段 id 靠手输弹窗；删除需手输 "yes"；诊断/审计结果用 `<pre>` 倾倒且截断
3. **写作核心缺失**：裸 textarea 无自动保存、无脏检查（切章直接丢未保存文本）、保存清空撤销栈、无 Ctrl+S、无实时字数
4. **AI 体验弱**：无流式输出（8000 token 干等几十秒）、聊天无 Markdown 渲染、AI 写回正文直接覆盖无 diff 预览
5. **有后端无 UI**：WebDAV 同步、检查更新、伏笔收/弃、时间线记录、九阶段流程等约 26 条命令无任何入口；无深色模式

## 改造总览（4 阶段）

按你未及时选择，采用推荐组合：**全面改造 / CodeMirror 6 编辑器 / 深色模式（白色默认）**，如需调整审批时说明即可。**core 业务层已有逻辑不动，282 个测试保持全绿；新 IPC 先改 packages/contracts；不推送不发布。**

### 阶段 1：UI 架构与布局重构

- **组件化拆分**：新增 `renderer/src/store/`（zustand，替换 35 字段大 useState）；拆出 `components/`：TopBar、ActivityRail（图标导航）、ProjectsPanel、**ChapterTreePanel**、LorebookPanel、WorkflowPanel、LibraryPanel、ToolboxPanel、EditorPane、RightPanel、ChatBar、`modals/`（统一 ConfirmDialog / SelectDialog / FormDialog / ResultDialog）
- **新布局**：顶栏（品牌+全局动作+窗口控制）/ 左栏图标导航切换面板（作品、世界书、创作流程、资料、工具）/ 中央编辑器（面包屑+工具栏+状态栏）/ 底部聊天栏（**可折叠、可拖拽调高**）
- **章节树替代下拉**：章节列表（编号+标题+字数）、搜索过滤、双击重命名、右键/hover 删除（走 ConfirmDialog）、新建章节；拖拽排序作为可选增强（需 core 新增 reorder 方法+单测+contracts 新命令，风险大则缓行）
- **弹窗现代化**：所有手输 id 改为下拉选择（数据来自 prompts:list、PHASE_ORDER、内置导出格式枚举）；删除确认改按钮式 ConfirmDialog；结果展示改 RightPanel 卡片+复制按钮
- **视觉升级**：沿用现有白底黑字 token 体系，增强层次（侧栏分组标题、空状态、加载骨架、焦点环）；清理死代码（.batch-form CSS、GENRES、未用的 pdfjs-dist）

### 阶段 2：写作体验

- **自动保存**：变更防抖 1.5s 自动保存 + Ctrl+S + 失焦保存；状态栏保存状态（未保存圆点）；切换章节/项目前的未保存保护
- **编辑器升级 CodeMirror 6**：写作排版（衬线正文、行距 1.8、居中可读宽度、段首缩进）、纯文本模式（不做代码高亮）；撤销/重做走 CM6 history（顺带修掉"保存清空撤销栈"）；查找替换用 CM6 search（全部高亮/上下导航）；AI 写回用事务替换；专注模式一键隐藏两侧
- **状态栏**：实时字数（core countChapter）、字符数、当前模型、保存状态
- **深色模式**：CSS 变量双主题、白色默认、跟随系统+手动切换、偏好经 settings:set 持久化

### 阶段 3：AI 体验

- **流式输出**（体感最大提升）：`main/model-service.ts` 新增 stream 路径（OpenAI SSE / Anthropic SSE / Gemini streaming，保留原 complete 兼容）；contracts 新增流式事件契约（preload 的 on() 通道已在，主进程补 webContents.send）；聊天与写章/润色流式渲染
- **聊天栏**：Markdown 渲染、消息复制、重新生成、发送中 spinner、错误气泡
- **写回 diff 预览**：AI 输出【编辑框结果】时不再直接覆盖——先弹出 diff 视图（复用 core diffSentences），用户点"应用"才写入
- **写章挂接题材模板**：resources/prompts 的 8 个 writing-chapter-* 模板接入写章 UI（按书 genre 默认选中）
- **模型设置优化**：卡片式列表、测试连通反馈、批量导入理顺

### 阶段 4：功能补全（后端已有、只缺 UI）

- **设置中心**：主题/字号/自动保存开关/数据目录/检查更新（update:check 已有）/版本信息
- **WebDAV 同步界面**：配置+测试连接+推送/拉取+上次同步结果（sync:* 5 条命令已有）
- **资料面板**：伏笔（种/收/弃）、时间线（记/看）、术语表、灵感、事实账本、一致性巡检——全部表格表单化，替代手输 id
- **创作流程面板**：九阶段进度可视化 + 各阶段产物（docs/*.md）查看编辑 + 提交/推进按钮
- **工具箱重组**：24 个按钮按类别分组折叠

## 实施与验证

- 每阶段结束验证：`NODE_OPTIONS= ` 前缀构建 + typecheck + `npx vitest run` 全绿 + 打包 win-unpacked 实际运行走查
- 新依赖：zustand、codemirror 6、react-markdown（均为成熟开源库）
- 风险规避：NODE_OPTIONS shim 按交接文档处理；CM6 封装在 EditorPane 内隔离；流式保留旧 complete 接口兼容
